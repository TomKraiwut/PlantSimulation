4. ความเสียหายของเครื่องจักร

วัตถุประสงค์การเรียนรู้

  1. เข้าใจแนวคิด MTTR/MTBF และผลกระทบต่อสายการผลิต
  2. ตั้งค่า Failure บน Object ประเภทประมวลผลได้

MTTR / MTBF คืออะไร

คำย่อความหมาย
MTBF (Mean Time Between Failures)เวลาเฉลี่ยระหว่างที่เครื่องจักรเสียแต่ละครั้ง — ยิ่งมากยิ่งเสียบ่อยน้อย
MTTR (Mean Time To Repair)เวลาเฉลี่ยที่ใช้ซ่อมแต่ละครั้ง — ยิ่งมากยิ่งซ่อมนาน

โมเดลที่ไม่มี Failure เลยจะให้ผล Throughput สูงเกินจริงเสมอ เพราะโรงงานจริงไม่มีเครื่องจักรที่ทำงานได้ 100% ตลอดเวลา

ตั้งค่า Failure บน Object

  1. ดับเบิลคลิกที่ Object ประเภทประมวลผล (เช่น Station) → ไปแท็บ Failures
  2. เลือกโหมด Failure — ที่พบบ่อยคือ Availability-based (กำหนดเปอร์เซ็นต์เวลาที่พร้อมใช้งาน) หรือ MTBF/MTTR (กำหนดตัวเลขทั้งสองค่าตรงๆ)
  3. กรอก MTBF และ MTTR (แต่ละค่าตั้งเป็น Distribution ได้เหมือนบทที่แล้ว เช่น เวลาซ่อมสุ่มตาม Exponential)
  4. รันซิมูเลชัน แล้วเปิด Statistics — จะเห็นสถานะใหม่ Failed/Down เพิ่มเข้ามานอกจาก Working/Waiting/Blocked
ข้อควรรู้: Failure มักตั้งแบบ "สุ่มตามเวลาทำงานสะสม" ไม่ใช่ "สุ่มตามเวลาปฏิทิน" — เครื่องที่ไม่มีงานทำ (Waiting) โดยทั่วไปจะไม่นับเป็นช่วงเวลาที่เดินไปสู่การเสีย เพราะยังไม่ได้ทำงานจริง

ตัวอย่างการวิเคราะห์

สถานี A: MTBF = 8 ชั่วโมง, MTTR = 30 นาที → คิดคร่าวๆ ว่าเครื่องพร้อมใช้งานประมาณ 8/(8+0.5) ≈ 94%

คำถามฝึกคิด: ถ้าวิเคราะห์แล้วพบว่าสถานีคอขวดมี Availability ต่ำมาก (เสียบ่อย) ทางเลือกในการแก้ปัญหามีอะไรบ้าง นอกจากซื้อเครื่องใหม่?
เฉลย: เพิ่ม Buffer ก่อน/หลังสถานีนั้นเพื่อดูดซับช่วงเวลาที่เสีย, ลด MTTR ด้วยการเตรียมอะไหล่/ทีมซ่อมให้เร็วขึ้น, หรือเพิ่มสถานีสำรองขนานเพื่อสลับใช้งานเวลาสถานีหลักเสีย — ลองปรับตัวแปรพวกนี้ในโมเดลเปรียบเทียบกันได้ก่อนตัดสินใจลงทุนจริง
