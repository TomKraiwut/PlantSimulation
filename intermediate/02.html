2. MU และ MU Class

วัตถุประสงค์การเรียนรู้

  1. เข้าใจว่า MU (Movable Unit) คืออะไร และทำไมต้องสร้าง MU class ของตัวเอง
  2. สร้างและกำหนดให้ Source ผลิต MU class ที่กำหนดเองได้

MU (Movable Unit) คืออะไร

MU คือ "ชิ้นงาน" ที่เคลื่อนที่ผ่านระบบ — เก็บอยู่ในหมวด Class Library MUs แบ่งเป็นประเภทหลักคือ Part (ชิ้นงานทั่วไป), Container (ภาชนะบรรจุหลายชิ้น), Transporter (พาหนะที่ขับเคลื่อนเอง)

ข้อควรรู้: Object ใต้ .MUs เป็น "แม่แบบ" ที่ Source จะผลิตสำเนาออกมาตอนรัน ไม่ใช่ Object ที่ลากไปวางบน Frame ได้โดยตรงแบบ Source/SingleProc — ถ้าอยากปรับแต่งคุณสมบัติของ MU (เช่น ตั้งชื่อ, สี, น้ำหนักเริ่มต้น) ต้อง Duplicate/Derive ก๊อปปี้ MU ไปไว้ในหมวด UserObjects ของตัวเองก่อน

สร้าง MU class ของตัวเอง

  1. ไปที่ Class Library → MUs → Part (หรือ Container/Transporter ตามต้องการ)
  2. คลิกขวา → Duplicate หรือ Derive แล้วลากไปวางใน UserObjects
  3. ตั้งชื่อให้สื่อความหมาย เช่น PartA
  4. เปิด Attribute ของ MU ที่สร้างใหม่ ปรับค่าเริ่มต้น (ไอคอน, สี, น้ำหนัก ฯลฯ) ตามต้องการ
  5. ไปที่ Source ที่จะผลิต MU นี้ → ตั้งค่าช่อง MU (แอตทริบิวต์ที่กำหนดคลาส MU ที่จะผลิต) ให้ชี้ไปที่ MU ที่สร้างไว้
Tip: ถ้ามี MU หลายแบบให้ Source ผลิตแบบสุ่มหรือเรียงลำดับ ให้ดูช่อง MUSelection ของ Source — เลือกโหมด Constant (คลาสเดียวคงที่), Sequence (เรียงลำดับ), หรือ Random (สุ่มตามสัดส่วน)
คำถามฝึกคิด: ทำไมลาก .MUs.Part ไปวางบน Frame ตรงๆ ไม่ได้เหมือน Source/SingleProc?
เฉลย: เพราะ Object ใต้ .MUs เป็นแม่แบบสำหรับให้ Source สร้างสำเนาขึ้นมาตอนรันจำลอง ไม่ใช่ Object ที่มีตำแหน่งตายตัวในผังโรงงาน — ต้อง Duplicate/Derive ไปเป็นของตัวเองก่อนถึงจะปรับแต่งและใช้อ้างอิงได้
