Plant Simulation Tutorial

6. SimTalk และภาพเคลื่อนไหว

วัตถุประสงค์การเรียนรู้

  1. ผูก Method เข้ากับ Button/DropDownList เพื่อสร้างแผงควบคุมได้
  2. เข้าใจการใช้ Method สั่งภาพเคลื่อนไหว 3 มิติ ไม่ใช่แค่คำนวณตัวเลข

อ้างอิงเฟรม Model_Method และ Model_3D_Animation — ควบคุมโมเดลด้วยโค้ด ผูก UI เข้ากับ Method และสั่งภาพเคลื่อนไหว ดู syntax เต็มๆ ที่ Advanced บทที่ 1

ผูก Method เข้ากับ UI — Button และ DropDownList

Objectใช้ทำอะไร
Buttonเรียก Method หนึ่งตัวเมื่อถูกคลิก — ผูกที่ Attribute Method ของปุ่ม
DropDownListให้ผู้ใช้เลือกค่าจากรายการ แล้วส่งค่าที่เลือกเข้า Method ผ่านตัวแปรที่ผูกไว้
  1. ลาก Button จากหมวด UserInterface มาวางบน Frame
  2. เปิด Attribute ของ Button → ช่อง Method → เลือก Method ที่สร้างไว้
  3. เขียนโค้ดใน Method ตามพฤติกรรมที่ต้องการ เช่น เปลี่ยนอัตราการผลิตของ Source
  4. ทำแบบเดียวกันกับ DropDownList โดยผูกค่าที่เลือกเข้าตัวแปร แล้วให้ Method อ่านค่านั้นไปใช้ต่อ
Tip: ปุ่มสองปุ่มในเฟรมนี้มักใช้สาธิตคู่ Start/Stop หรือ Slow/Fast — แยก Method คนละตัวชัดเจน ดีกว่ารวมไว้ใน Method เดียวแล้วเช็คเงื่อนไข เพราะดีบักง่ายกว่าเมื่อโมเดลใหญ่ขึ้น

Model_3D_Animation — สั่งภาพเคลื่อนไหวด้วย Method

เฟรมนี้มี Method เพียงตัวเดียวแต่ผูกกับสายการผลิตที่มีทั้ง Station และ PickAndPlace — สาธิตว่า Method ไม่ได้ใช้แค่คำนวณ ค่าตัวเลข แต่ยังสั่งเปลี่ยนรูปลักษณ์/การหมุน/สีของ MU ในมุมมอง 3D ได้โดยตรงผ่าน Attribute ของ MU เอง ทำให้แอนิเมชันสื่อความ หมายมากกว่าดูแค่ Object เคลื่อนที่เฉยๆ

ทำไมสำคัญ: เมื่อพรีเซนต์โมเดลให้ผู้บริหารหรือลูกค้าดู ภาพเคลื่อนไหวที่สื่อความหมาย (เช่น ชิ้นงานเปลี่ยนสีตอนผ่าน QC) ช่วยให้เข้าใจ Logic ได้เร็วกว่าตัวเลขสถิติล้วนๆ มาก
คำถามฝึกคิด: ควรผูก Method ไว้ที่ ExecuteAt.Entrance หรือ ExecuteAt.Exit ถ้าต้องการนับจำนวน ชิ้นงานที่ "ผ่านสำเร็จ" ออกจากสถานี?

เฉลย: ExecuteAt.Exit — เพราะชิ้นงานที่เข้า (Entrance) อาจยัง ประมวลผลไม่เสร็จหรือถูกดีดออกเพราะ Error ได้ การนับที่จุดออกจริงเท่านั้นที่ยืนยันว่าสถานีทำงานสำเร็จกับชิ้นงานนั้นแล้ว
