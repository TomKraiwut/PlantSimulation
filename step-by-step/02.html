Plant Simulation Tutorial

2. สถิติและการวิเคราะห์

วัตถุประสงค์การเรียนรู้

  1. ใช้ Chart หลายตัวตอบคำถามคนละแบบในเฟรมเดียวกันได้
  2. เข้าใจรูปแบบตาราง ORDER/CT/ST แบบ data-driven และวิธีคำนวณ OEE

อ้างอิงเฟรม Model_Chart, Model_Data_Table, Model_OEE, Model_EnergyAnalyzer — อ่านผลลัพธ์การจำลอง จัดเก็บข้อมูลด้วยตาราง และคำนวณ OEE / พลังงาน

Object ในเฟรมต้นฉบับ: Model_Chart มี Chart ×3, Display ×4 — Model_Data_Table เพิ่ม DataTable ORDER/CT/ST — Model_OEE เพิ่ม Display สำหรับ Availability/Performance/Quality/OEE — Model_EnergyAnalyzer ฝังเฟรมย่อย EnergyAnalyzer และ GAWizard

Chart หลายตัว ตอบคนละคำถาม

เฟรม Model_Chart มี Chart ถึง 3 ตัวเพราะ Chart หนึ่งตัวแสดงได้แค่มุมมองเดียว — ต้องแยก Chart ตามคำถามที่อยาก ตอบ เช่น สัดส่วนเวลา Working/Waiting/Blocked ของ Station, จำนวนชิ้นงานสะสมที่ Drain ตามเวลา, และปริมาณ WIP ใน Buffer

Tip: ใช้ Display คู่กับ Chart เสมอสำหรับตัวเลขที่ต้องอ่านแม่นยำ (เช่น Throughput สะสม) — Chart เหมาะกับ "แนวโน้ม/สัดส่วน" ส่วน Display เหมาะกับ "ตัวเลขล่าสุด"

DataTable — ขับเคลื่อนโมเดลด้วยข้อมูล

ตารางความหมาย
ORDERรายการคำสั่งผลิต — ชนิดชิ้นงาน/จำนวนที่ต้องผลิตในแต่ละรอบ
CT (Cycle Time)เวลาแปรรูปของแต่ละชนิดชิ้นงานที่แต่ละสถานี
ST (Setup Time)เวลาปรับตั้งเครื่องเมื่อเปลี่ยนชนิดชิ้นงาน

แทนที่จะพิมพ์เวลาแปรรูปตายตัวใน Station แต่ละตัว ให้ Station ดึงค่าจากตารางตามชนิดชิ้นงานที่กำลังประมวลผล — bracket indexing ตัวเดียวกับที่สอนใน Advanced บทที่ 3:

->void;
var partType := @.PartType
Station.procTime := CT[partType, Station.name]
ทำไมต้องทำแบบนี้: เมื่อมีหลายชนิดชิ้นงาน การแก้ไขเวลาแปรรูปทำที่ตารางเดียว ไม่ต้องไล่แก้ทีละ Station — เป็นพื้นฐานสำคัญก่อนไปบทที่ 8 (Optimization) ที่ต้องปรับค่าจากภายนอกโมเดลได้

OEE — Overall Equipment Effectiveness

องค์ประกอบความหมาย
Availabilityสัดส่วนเวลาที่เครื่องพร้อมทำงาน (ไม่รวมเวลาหยุดเสีย/ตั้งเครื่อง)
Performanceสัดส่วนความเร็วจริงเทียบกับความเร็วสูงสุดที่ออกแบบไว้
Qualityสัดส่วนชิ้นงานดีเทียบกับชิ้นงานทั้งหมดที่ผลิต
OEEAvailability × Performance × Quality — ตัวชี้วัดประสิทธิภาพรวม

OEE คำนวณจาก Statistics ของ Station โดยตรงผสมกับจำนวนชิ้นงานดี/เสียที่นับได้จาก Drain สองตัวในเฟรมนี้ ไม่จำเป็นต้องมี Object พิเศษเพิ่ม — ใช้ Method คำนวณสามค่าแล้วคูณกันได้เลย

EnergyAnalyzer — วิเคราะห์การใช้พลังงาน

เฟรม Model_EnergyAnalyzer ฝัง Object เครื่องมือ EnergyAnalyzer ไว้เป็นเฟรมย่อย ใช้ประเมิน พลังงานที่ใช้ในแต่ละสถานะของเครื่องจักร (Working/Standby/Off) เหมาะสำหรับวิเคราะห์ต้นทุนพลังงานควบคู่กับ Throughput ก่อน ตัดสินใจเพิ่ม/ลดจำนวนเครื่องจักร เฟรมนี้ยังฝัง GAWizard ไว้ด้วย เป็นจุดเริ่มก่อนเข้าเนื้อหาเต็มที่ บทที่ 8: Optimization ด้วย GAWizard

คำถามฝึกคิด: ถ้า OEE ของสถานีหนึ่งต่ำ ควรดูค่าไหนก่อน (A, P, หรือ Q) เพื่อรู้ว่าปัญหาหลักคืออะไร?

เฉลย: ดูทั้งสามค่าแยกกันเสมอ — A ต่ำมักบ่งชี้ปัญหาการหยุดเครื่อง/รอวัตถุดิบ, P ต่ำบ่งชี้เครื่องทำงานช้ากว่าที่ ออกแบบ, Q ต่ำบ่งชี้ปัญหาคุณภาพต้นทาง — ค่า OEE รวมค่าเดียวไม่บอกว่าควรแก้ตรงไหนก่อน
