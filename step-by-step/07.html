7. โมเดล 3 มิติ

วัตถุประสงค์การเรียนรู้

  1. รู้จัก Object เฉพาะมุมมอง 3 มิติ (AngularConverter, Turntable, Turnplate)
  2. เข้าใจว่าทำไมต้องตรวจสอบ Object กลุ่มนี้ในมุมมอง 3 มิติเสมอ

อ้างอิงเฟรม Model_3D_Factory — Object เฉพาะที่มีความหมายในมุมมอง 3 มิติเท่านั้น สำหรับเปลี่ยนทิศทาง/ ระดับความสูงของชิ้นงานบนสายพาน

ทำไมต้องมี Object เฉพาะสำหรับ 3D

ในมุมมอง 2D สายพานทุกเส้นวาดเป็นเส้นตรงหรือหักมุมได้อิสระโดยไม่ต้องมี Object พิเศษ แต่ในโรงงานจริง การเปลี่ยนทิศทาง/ระดับ ของสายพานต้องใช้อุปกรณ์จริงซึ่งกินพื้นที่และเวลา — เฟรมนี้รวม Object ที่จำลองอุปกรณ์เหล่านั้นไว้ในที่เดียว

Objectใช้ทำอะไร
AngularConverterเปลี่ยนทิศทางการไหลของชิ้นงานเป็นมุมที่กำหนด ระหว่างสายพานสองเส้น
Turntableโต๊ะหมุนที่หมุนตัวชิ้นงานเองเพื่อเปลี่ยนทิศทางออก ชิ้นงานหยุดนิ่งบนโต๊ะระหว่างหมุน
Turnplateคล้าย Turntable แต่มักใช้กรณีต้องหมุนพร้อมส่งต่อแบบต่อเนื่องมากกว่า

ทั้งสามตัวอยู่ในหมวด MaterialFlow เช่นเดียวกับ Conveyor — วางแทรกระหว่างสองเส้นทางได้เหมือน Object ลำเลียงทั่วไป ต่างกันแค่ตอนตั้งค่ามุม/ทิศทางที่ Attribute

  1. วาง Conveyor เส้นแรกเข้า AngularConverter หรือ Turntable
  2. ตั้งค่ามุมการเปลี่ยนทิศทางที่ Attributes (เช่น 90° สำหรับเลี้ยวฉาก)
  3. ต่อ Conveyor เส้นที่สองออกจากอุปกรณ์นั้นในทิศทางใหม่
  4. สลับมุมมองเป็น 3D เพื่อตรวจสอบว่าชิ้นงานเปลี่ยนทิศทาง/หมุนตามที่ตั้งค่าจริง
Tip: ในมุมมอง 2D อุปกรณ์เหล่านี้อาจดูเหมือนจุดเชื่อมธรรมดา — ต้องสลับไปมุมมอง 3D เพื่อตรวจสอบ ว่าตั้งค่ามุม/ทิศทางถูกต้องจริง อย่าพึ่งพา 2D อย่างเดียวเมื่อใช้ Object กลุ่มนี้

เฟรมนี้ยังฝัง WorkerPool + Broker + Workplace (จาก บทที่ 4) ไว้ด้วย เพื่อสาธิตโมเดล ระดับใกล้เคียงโรงงานจริงที่ต้องผสมทั้งการขนย้าย 3 มิติและแรงงานคนในเฟรมเดียวกัน

คำถามฝึกคิด: ทำไมควรตรวจสอบ Turntable/Turnplate ในมุมมอง 3D เสมอ ทั้งที่โปรแกรมรัน ซิมูเลชันได้ปกติแม้ไม่เปิดมุมมอง 3D?

เฉลย: ผลลัพธ์ตัวเลขถูกต้องได้แม้ตั้งค่าทิศทาง/มุมผิด เพราะ Logic การไหลของชิ้นงานคำนวณแยกจากภาพ 3D — แต่ถ้านำโมเดลไปพรีเซนต์หรือใช้ตรวจสอบพื้นที่จริง มุมที่ผิดจะทำให้ข้อสรุปเรื่อง พื้นที่หน้างานผิดพลาดโดยที่ตัวเลขไม่ฟ้องเลย
