SimTalk 2.0 คืออะไร

SimTalk คือภาษาสคริปต์ของ Plant Simulation เขียนใน Object ประเภท Method เพื่อสั่งงาน กำหนดเงื่อนไข หรือดึง/เปลี่ยนค่าตัวแปรของ Object อื่นในโมเดล เนื้อหาบทนี้อ้างอิง syntax ที่ทดสอบรันได้จริง (SimTalk 2.0) ไม่ใช่ syntax แบบเก่า (is...do...end) ที่อาจเจอในเอกสารเก่าหรือโมเดลรุ่นก่อน

หมายเหตุ: ถ้าเจอโมเดลเก่าที่เขียนด้วย syntax is / do / end คั่นด้วย -- comment นั่นคือ SimTalk รุ่นก่อนหน้า ยังใช้งานได้ในโมเดลเดิม แต่โค้ดใหม่ที่เขียนควรใช้ syntax ของ SimTalk 2.0 ตามบทนี้แทน

โครงสร้าง Method

Method ทุกตัวต้องมีบรรทัด header ก่อนตัวเนื้อโค้ด บอกชนิดค่าที่ return (หรือไม่ return ก็ได้):

->string;              // ไม่มีพารามิเตอร์ คืนค่าเป็น string
var buf := "hello"
return buf

หรือมีพารามิเตอร์:

param x: integer := 0 -> integer;
return x + 1

Syntax พื้นฐานที่ยืนยันแล้ว

ConstructSyntaxหมายเหตุ
ประกาศตัวแปรvar x := <expr>ไม่ต้องระบุชนิดตัวแปร (อนุมานอัตโนมัติ) ไม่มี ; ปิดท้าย
for-loopfor var i := 1 to N ... nextไม่มีคำว่า loop/do ปิดด้วย next ไม่ใช่ end
ifif <cond> ... endไม่มีคำว่า then
ต่อ string"a" + "b"ใช้ + ธรรมดา
ตัวอักษรจาก code pointstrChr(31)สร้างตัวคั่นพิเศษที่ไม่ชนกับชื่อ Object
คำสงวนresultห้ามใช้เป็นชื่อตัวแปร (var result := ... error) ใช้ชื่ออื่นแทน เช่น buf, acc

ตัวอย่างจริง: วนลูปอ่านชื่อ Object ทุกตัวใน Frame

->string;
var buf := ""
for var i := 1 to .Models.Model.NumNodes
    buf := buf + .Models.Model.Node(i).Name + strChr(31) + .Models.Model.Node(i).InternalClassType + strChr(30)
next
return buf
คำถามฝึกคิด: ทำไมโค้ดตัวอย่างข้างบนใช้ strChr(31)/strChr(30) คั่นข้อมูล แทนที่จะใช้ comma หรือ space ธรรมดา?
เฉลย: เพราะชื่อ Object จริงอาจมี comma หรือ space ปนอยู่ในชื่อได้ ถ้าใช้ตัวคั่นทั่วไปอาจแยกข้อมูลผิดพลาด strChr(31)/strChr(30) คือ Unit/Record Separator ซึ่งแทบไม่มีทางปรากฏในชื่อ Object จริง จึงปลอดภัยกว่า
