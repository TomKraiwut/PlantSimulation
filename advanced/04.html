4. สร้าง Object ด้วยโค้ด

วัตถุประสงค์การเรียนรู้

  1. สร้าง Frame และ Object ด้วย createObject จากโค้ดล้วนๆ ได้
  2. เชื่อมต่อ Object ด้วย Connector.connect และทำให้ Transporter ขับเคลื่อนเองได้

สร้าง Object ด้วยโค้ด: createObject

การสร้าง Object เป็นการเรียก method บน class template เอง ไม่ใช่ global function:

var f := .MaterialFlow.Frame.createObject(.Models, 0, 0)
f.Name := "Transporting"
var src := .MaterialFlow.Source.createObject(f, 50, 100)
src.Name := "Source"
กติการายละเอียด
container ต้องเป็น Frame หรือ Folderอย่างอื่น error "Argument 1 is neither a Frame nor a Folder"
x, y เป็นตำแหน่งบังคับไม่มี overload แบบไม่ระบุตำแหน่ง
Object ใหม่ได้ชื่ออัตโนมัติควรตั้งชื่อเองทันทีผ่าน obj.Name := "..."

เชื่อมต่อ Object: Connector.connect

.MaterialFlow.Connector.connect(src, trk)
.MaterialFlow.Connector.connect(trk, drn)

สร้าง Connector จริงเหมือนลากด้วยมือ ตรวจสอบได้ด้วย obj.succ(1) ซึ่งอ่านค่า Object ถัดไปที่เชื่อมอยู่

ทำให้ Transporter ขับเคลื่อนเอง (จุดที่มักพลาด)

Transporter ที่ Duplicate มาวางบน Track แล้ว แม้ตั้ง Speed ไว้ก็ยังไม่วิ่งถ้าไม่ตั้งค่าทั้งสองนี้ครบ:

veh.Destination := drn          // ปลายทางที่ต้องไปถึง
veh.AutomaticRouting := true    // ให้คำนวณเส้นทางเองผ่าน Connector
กับดักตอนเช็คผล: เช็คว่าชิ้นงานถึงปลายทางหรือยังด้วย Drain.StatDeleted (จำนวนสะสมที่ Drain เคยทำลายไปแล้ว) ไม่ใช่ Drain.NumMU (จำนวนที่อยู่ในนั้น ณ ขณะนี้ ซึ่งเป็น 0 เสมอเพราะ Drain ทำลายชิ้นงานทันทีที่รับเข้า) เช็คตัวหลังผิดจะดูเหมือนโมเดลค้าง ทั้งที่จริงทำงานถูกต้องอยู่แล้ว
คำถามฝึกคิด: รันโมเดลที่สร้างด้วยโค้ดไปไม่กี่วินาที แล้ว Drain.StatDeleted ยังเป็น 0 อยู่ ควรสรุปว่าโมเดลพังทันทีหรือไม่?
เฉลย: ยังสรุปไม่ได้ — โมเดลใหม่ที่สร้างด้วย app.NewModel() มักรันใกล้เคียงเวลาจริง (ไม่เร็วจัดเหมือนโมเดลสำเร็จรูปบางไฟล์) และ ProcTime ดีฟอลต์มักอยู่ราว 10 วินาที ควรเช็ค EventController.SimTime ว่าเวลาจำลองเดินไปเท่าไหร่แล้ว และเช็ค NumMU ของแต่ละสถานีว่าชิ้นงานติดอยู่ตรงไหนก่อนสรุปว่าพัง
