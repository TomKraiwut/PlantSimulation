3. DataTable และ Variable

วัตถุประสงค์การเรียนรู้

  1. สร้างและเข้าถึง DataTable/Variable จากโค้ดได้ โดยไม่ติดกับดัก auto-deref
  2. อ่าน-เขียนค่าในตารางด้วย bracket indexing ได้ถูกต้อง

DataTable และ Variable อยู่ใต้ .InformationFlow

ต่างจาก Object การไหลของวัสดุ (.MaterialFlow) — DataTable และ Variable อยู่ในหมวด .InformationFlow สร้างด้วย createObject แบบเดียวกับ Object ทั่วไป:

var t := .InformationFlow.DataTable.createObject(f, 0, 0)
t.Name := "Items"
กับดัก auto-deref: การอ้าง .InformationFlow.Variable เฉยๆ (ไม่ผ่าน .Node()) จะได้ ค่าที่ตัวแปรถืออยู่ (ค่าเริ่มต้นเป็น 0) ไม่ใช่ตัว Object เอง ทำให้ createObject พัง — ต้องใช้ .Node("ClassName") เพื่อขอ object reference ตรงๆ แทน: 
var v := .InformationFlow.Node("Variable").createObject(f, 0, 50)
v.Name := "Constraint"

กติกาเดียวกันนี้ใช้กับ Method ด้วย (บทที่ 2) — เป็นกฎทั่วไปของ Object ในหมวด .InformationFlow ที่ "มีค่า" หรือ "เรียกใช้ได้" ไม่ใช่เฉพาะ Variable

อ่าน/เขียนค่าใน DataTable

ใช้ bracket indexing [column, row] โดยทั้งคู่เริ่มนับที่ 1:

return to_str(.Models.Model.DataTable[1, 1])   // อ่านค่า
.Models.Model.DataTable[1, 1] := "hello"       // เขียนค่า
กติการายละเอียด
ไม่มี getValue/setValueเข้าถึงด้วย bracket indexing เท่านั้น
แถว/คอลัมน์ 0 = หัวตารางtable[c, 0] อ่านชื่อคอลัมน์, table[0, r] อ่านชื่อแถว
XDim/YDim อ่านได้อย่างเดียวแต่การเขียนค่าเกินขอบเขตปัจจุบันจะขยายตารางอัตโนมัติ
คอลัมน์ใหม่เป็น string โดยดีฟอลต์เขียนตัวเลขตรงๆ (เช่น table[1,1] := 99) จะ error ต้องเขียนเป็น string เช่น "99" จนกว่าจะตั้งชนิดคอลัมน์ผ่าน GUI
คำถามฝึกคิด: ทำไม .InformationFlow.Variable.createObject(...) ถึง error ว่า "A 'integer' cannot accept the method 'createObject'"?
เฉลย: เพราะ path เปล่าๆ ไปที่ Variable auto-deref กลายเป็นค่า integer (ค่าเริ่มต้น 0) ของตัวแปรนั้นไปแล้ว ไม่ใช่ตัว Object — ต้องใช้ .Node("Variable") เพื่อขอ Object reference ก่อนเรียก createObject
