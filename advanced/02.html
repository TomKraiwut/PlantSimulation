2. Method ผูกกับ Event

วัตถุประสงค์การเรียนรู้

  1. ผูก Method เข้ากับเหตุการณ์ Entrance/Exit ของสถานีได้
  2. ใช้ Trigger ให้ Method ทำงานเป็นระยะเวลาซ้ำๆ ได้

ผูก Method เข้ากับเหตุการณ์ Entrance/Exit

Object ประเภทประมวลผล (เช่น SingleProc) มีช่อง ExecuteAt.Entrance และ ExecuteAt.Exit ให้กำหนด Method ที่จะทำงานอัตโนมัติทุกครั้งที่มีชิ้นงานเข้า/ออกจากสถานีนั้น

  1. สร้าง Method object ในหมวด InformationFlow ตั้งชื่อ เช่น OnEntry
  2. เขียนโค้ดใน Method นั้น
  3. ที่ Object เป้าหมาย (เช่น SingleProc) เปิด Attribute → ช่อง ExecuteAt.Entrance → กำหนดให้ชี้ไปที่ Method OnEntry
  4. รันซิมูเลชัน — Method จะถูกเรียกอัตโนมัติทุกครั้งที่มีชิ้นงานเข้าสถานี ไม่ต้องเรียกเองด้วยมือ

เข้าถึงชิ้นงาน (MU) ปัจจุบัน

ภายใน Method ที่ผูกกับเหตุการณ์แบบนี้ ตัวแปรพิเศษ @ อ้างอิงถึง MU (ชิ้นงาน) ที่กำลังผ่านสถานีอยู่ขณะนั้น

->void;
var mu := @
print "MU " + mu.Name + " entered station"

Trigger: ทำงานเป็นระยะเวลาซ้ำๆ

ถ้าต้องการให้ Method ทำงานตามเวลา (ไม่ผูกกับเหตุการณ์ของ Object อื่น) ใช้ Object Trigger (อยู่ในหมวด InformationFlow) ตั้งค่าคาบเวลาที่ต้องการ แล้วกำหนดให้เรียก Method ที่ต้องการทุกครั้งที่ครบคาบ

รูปแบบทั่วไป: Attribute เก็บ reference ไปยัง Method

สอดคล้องกับรูปแบบที่ใช้ซ้ำทั่วทั้งโปรแกรม — แอตทริบิวต์ที่ควบคุมพฤติกรรม (เช่น Ctrl ของเซนเซอร์บางประเภท) เก็บ object reference ไปยัง Method โดยตรง กำหนดค่าได้จากโค้ดเช่นกัน:

someSensor.Ctrl := .Models.MyFrame.Node("MyControlMethod")
คำถามฝึกคิด: ถ้าอยากนับจำนวนชิ้นงานที่ผ่านสถานีสะสมตลอดการรัน ควรผูก Method กับ Entrance หรือ Exit?
เฉลย: ทั้งสองจุดนับได้ในทางทฤษฎี แต่ Exit แม่นยำกว่าสำหรับนับ "งานที่เสร็จสมบูรณ์" เพราะ Entrance นับตอนเข้า ซึ่งชิ้นงานอาจยังไม่ผ่านกระบวนการจริง (เช่น ถ้าสถานีเสียระหว่างประมวลผล) — เลือกจุดผูกให้ตรงกับความหมายของสิ่งที่ต้องการวัด
